# Tune — гитарный тюнер для Android

Спецификация MVP. Версия 1.0, 2026-09-28.

---

## 1. Цель и границы

**Что делаем:** одноэкранное офлайн-приложение, которое слушает микрофон, определяет
частоту звучащей струны и показывает отклонение от цели в центах. Без аккаунтов, сети,
рекламы и аналитики.

**В MVP входит:**

- захват звука с микрофона, детект высоты тона в диапазоне 60–1400 Гц;
- автоматический выбор ближайшей струны текущего строя + ручная фиксация струны;
- строи: Standard (E A D G B E), Drop D, Half-step down, Open G, DADGAD;
- калибровка эталона A4 в диапазоне 415–466 Гц (по умолчанию 440);
- выбор ближайшей струны текущего строя, включая сильно расстроенные струны;
- индикация «в строе» цветом, положением стрелки и тактильным отзывом;
- тёмная/светлая тема, интерфейс на английском, поддержка TalkBack.

**Вне MVP (осознанно):**

- работа в фоне / foreground service (Android 14+ требует `FOREGROUND_SERVICE_MICROPHONE`
  и отдельного обоснования в Play — для тюнера не нужно);
- полифонический детект (все 6 струн одновременно);
- метроном, библиотека аккордов, запись, экспорт;
- Wear OS, планшетные multi-pane раскладки (но UI не должен ломаться на широком экране);
- ML-детект (Pitch Detection на TFLite) — избыточно, YIN даёт лучшую точность дешевле;
- бас-гитара, укулеле, другие инструменты: диапазон и константы DSP рассчитаны только под
  6-струнную акустическую гитару;
- внешние и Bluetooth-микрофоны, гарнитуры, линейный вход — работаем исключительно со
  встроенным микрофоном (§3.2).

**Критерий «готово»:** см. §11.

## 2. Пользовательские сценарии

1. **Быстрая подстройка.** Открыл приложение → сразу видит стрелку → щипнул струну →
   через <150 мс видит «A2 −7 ¢» → подтянул → стрелка в центре, вибро-щелчок.
2. **Первый запуск.** Показан экран с объяснением, зачем нужен микрофон → «Разрешить» →
   системный диалог → тюнер работает.
3. **Отказ в разрешении.** Экран-заглушка с кнопкой «Открыть настройки» (deep link в
   App Info), без повторного насильного диалога.
4. **Смена строя.** Свайп/тап по кнопке строя → bottom sheet со списком → выбор
   сохраняется между запусками.
5. **Шумное помещение.** RMS ниже порога или сигнал апериодичный → последнее устойчивое
   показание сохраняется без дёргания; до первого распознавания видна подпись «Play a string».

## 3. Android-специфика: захват звука

Это самая «андроидная» часть приложения и главный источник ошибок в тюнерах.

### 3.1 Разрешение

- `<uses-permission android:name="android.permission.RECORD_AUDIO"/>` — единственное
  разрешение приложения. `INTERNET` **не запрашиваем** (это заявление о приватности,
  которое проверяемо; упростит Data Safety в Play).
- `<uses-feature android:name="android.hardware.microphone" android:required="true"/>`.
- Запрос через Activity Result API (`rememberLauncherForActivityResult(RequestPermission())`),
  не через устаревший `onRequestPermissionsResult`.
- Порядок: своя карточка с объяснением → системный диалог. При отказе проверяем
  `shouldShowRequestPermissionRationale`: `false` после отказа = «больше не спрашивать» →
  ведём в `Settings.ACTION_APPLICATION_DETAILS_SETTINGS`.
- Разрешение может быть отозвано, пока приложение в фоне (и auto-revoke для неиспользуемых
  приложений) — состояние проверяем в `onStart`, а не один раз при создании.

### 3.2 Источник и параметры AudioRecord

```kotlin
// Приоритет источников: UNPROCESSED отдаёт сырой сигнал без AGC/NS/AEC.
val source = when {
    audioManager.getProperty(AudioManager.PROPERTY_SUPPORT_AUDIO_SOURCE_UNPROCESSED) == "true" ->
        MediaRecorder.AudioSource.UNPROCESSED
    else -> MediaRecorder.AudioSource.VOICE_RECOGNITION // обычно без AGC, в отличие от MIC
}

val record = AudioRecord.Builder()
    .setAudioSource(source)
    .setAudioFormat(
        AudioFormat.Builder()
            .setEncoding(AudioFormat.ENCODING_PCM_FLOAT) // API 23+, избавляет от ручной нормализации
            .setSampleRate(48_000)                       // нативная частота входа на большинстве устройств
            .setChannelMask(AudioFormat.CHANNEL_IN_MONO)
            .build()
    )
    .setBufferSizeInBytes(minBufferBytes * 4)             // x4 запас против переполнения
    .build()
```

Правила:

- **Не доверять запрошенным параметрам.** После создания читаем `record.sampleRate`,
  `record.format`, `record.state == STATE_INITIALIZED`. Если 48 000 не поддержано — фоллбэк
  на 44 100, потом на `AudioRecord.getMinBufferSize`-совместимую. Реальный sample rate
  прокидываем в DSP: ошибка в частоте дискретизации = систематическая ошибка в центах.
- **Глушим обработку сигнала.** Даже с `VOICE_RECOGNITION` некоторые вендоры включают
  эффекты. После создания `AudioRecord` по его `audioSessionId`:
  `AutomaticGainControl`, `NoiseSuppressor`, `AcousticEchoCanceler` — если
  `isAvailable()`, создаём и `setEnabled(false)`, держим ссылки до `release()`.
  AGC ломает амплитудную огибающую, NS выедает низкие частоты (страдает E2 = 82 Гц).
- **`setPrivacySensitive(false)`** — единственное место с `Build.VERSION` проверкой
  (API 30+; на Android 10 такого флага просто нет). По умолчанию для UNPROCESSED он может
  быть `true`, а тюнеру незачем блокировать одновременную запись другим приложениям.
- **Только встроенный микрофон.** Гарнитуры, внешние и Bluetooth-микрофоны не
  поддерживаются: SCO-канал 8/16 кГц бесполезен для определения питча, а гарнитурный тракт
  почти всегда идёт через вендорную обработку сигнала. Находим `TYPE_BUILTIN_MIC` в
  `audioManager.getDevices(GET_DEVICES_INPUTS)` и жёстко фиксируем его через
  `record.setPreferredDevice(...)` — иначе система сама уведёт вход на воткнутые наушники
  или подключённую BT-гарнитуру. Если встроенного микрофона нет — состояние ошибки.
  `AudioDeviceCallback` и отслеживание смены устройств не нужны: вход не меняется никогда.

### 3.3 Поток чтения

- Отдельный поток, не корутина на `Dispatchers.Default`: приоритет ставим явно —
  `Process.setThreadPriority(Process.THREAD_PRIORITY_URGENT_AUDIO)`.
- Блокирующее `record.read(buffer, 0, n, AudioRecord.READ_BLOCKING)`; отрицательный
  результат (`ERROR_DEAD_OBJECT` и др.) → полный пересоздание движка с backoff.
- **Ноль аллокаций в цикле:** переиспользуемые `FloatArray`, ring buffer на
  `FloatArray(2 * windowSize)`, результаты пишем в `MutableStateFlow<PitchReading>`
  (value-класс из примитивов). Никакого `List<Float>`, боксинга и `Flow` с буферами.
- Результаты в UI отдаём через `StateFlow` + `collectAsStateWithLifecycle()`; conflate
  по своей природе — UI читает последнее значение, кадры не копятся.

### 3.4 Микрофон могут забрать

С Android 10+ при конкуренции за микрофон привилегированное приложение (звонок,
ассистент) получает поток, а мы — **тишину без ошибок**. Тюнер, который в этот момент
показывает «0 Гц», выглядит сломанным.

- Регистрируем `AudioManager.registerAudioRecordingCallback` (есть с API 29, то есть с
  нашего `minSdk` — без версионных веток) и отслеживаем
  `AudioRecordingConfiguration.isClientSilenced` → показываем «Микрофон занят другим
  приложением».
- Плюс страховка: если RMS ровно 0 дольше 1.5 с при активной записи — тот же экран.

### 3.5 Жизненный цикл, экран, батарея

- Запись стартует в `onStart`/`LifecycleResumeEffect` и **гарантированно** останавливается
  и освобождается в `onStop` — микрофон в фоне даёт индикатор приватности в статус-баре и
  жрёт батарею. `release()` в `DisposableEffect`/`ViewModel.onCleared` недостаточно.
- Экран не гасим через `FLAG_KEEP_SCREEN_ON` на всё окно, а точечно:
  `DisposableEffect { view.keepScreenOn = true; onDispose { view.keepScreenOn = false } }`,
  и только когда тюнер активен. Опция в настройках (по умолчанию включено).
- Конфигурационные смены (поворот, тема, размер шрифта) не должны рвать запись: движок
  живёт в `ViewModel`, а не в `Activity`.
- `enableEdgeToEdge()` в `onCreate` + отступы через `WindowInsets`: с targetSdk 35+
  edge-to-edge принудительный, без insets контент уедет под системные бары.

## 4. DSP: определение высоты тона

### 4.1 Требования к точности

| Параметр | Значение |
|---|---|
| Диапазон | 65–1400 Гц (низ — D2 73.42 в Drop D/DADGAD плюс запас на сильно опущенную струну; верх — флажолеты и каподастр до E6 1318.5) |
| Точность | ±1 цент (типично ±0.3 на чистом сигнале) |
| Задержка «щипок → стрелка» | ≤ 150 мс |
| Частота обновления | ≥ 20 раз/с |
| Порог сигнала | −45 dBFS |

Почему это нетривиально: 1 цент на E2 — это 0.048 Гц. Прямой FFT на окне 4096 @48 кГц
даёт бин 11.7 Гц, то есть ~240 центов на бин — интерполяция по спектру не спасает при
негармоничных обертонах гитары. Поэтому работаем во временной области.

### 4.2 Алгоритм (конвейер)

1. **DC removal** — однополюсный high-pass (`y[n] = x[n] − x[n−1] + 0.995·y[n−1]`).
2. **Антиалиасинговый low-pass + децимация ×2** → 24 кГц. Для питча всё выше ~2 кГц —
   мусор; децимация вдвое снижает стоимость YIN вчетверо и убирает высокочастотный шум,
   провоцирующий октавные ошибки. Фильтр — 4-й порядок Butterworth (biquad-каскад),
   срез 2.5 кГц.
3. **Гейт по RMS.** Ниже −45 dBFS → `PitchReading.Silence`, детект не запускаем (экономия
   CPU и батареи в паузах — большая часть времени работы приложения).
4. **YIN** на окне 2048 сэмплов @24 кГц (85 мс), шаг 512 (21 мс):
   - разностная функция `d(τ)` для τ ∈ [17, 370] (что соответствует 1412…65 Гц);
   - кумулятивная нормализация (CMNDF) `d'(τ)`;
   - первый локальный минимум ниже порога `0.12`; если нет — берём глобальный минимум и
     помечаем низкой уверенностью;
   - **параболическая интерполяция** по трём точкам вокруг минимума — обязательна: без неё
     шаг в 1 сэмпл на E2 даёт ошибку ~12 центов;
   - `confidence = 1 − d'(τ*)`.
   Стоимость: 2048×370 ≈ 0.76 M MAC на кадр, ~47 кадров/с — доли процента CPU.
5. **Защита от октавной ошибки.** Проверяем `d'(τ*/2)`: если минимум на половинном лаге
   сопоставим (в пределах 15 %), выбираем более низкую частоту (истинную основную) —
   классическая ловушка на басовых струнах с сильной второй гармоникой.
6. **Сглаживание.** Медиана по 5 последним оценкам (убивает выбросы) → EMA с α ≈ 0.25 по
   *логарифму* частоты (в центах, не в герцах — иначе сглаживание несимметрично).
7. **Фиксация ноты (гистерезис).** Выбранная струна/нота не переключается, пока отклонение
   не выйдет за ±60 центов и не продержится 3 кадра. Без этого дисплей мигает между
   соседними нотами на границе.

**Почему свой YIN, а не библиотека.** TarsosDSP — де-факто стандарт для JVM, но его нет в
Maven Central (проверено: `be.tarsos.dsp:*` отсутствует), только JitPack-сборки; тянуть
JitPack в релизный build ради ~120 строк проверяемого кода — плохой обмен. YIN пишем сами
в отдельном чистом Kotlin-модуле, полностью покрытом unit-тестами (§10). Если позже
понадобятся MPM/спектральные фичи — TarsosDSP можно подключить, интерфейс `PitchDetector`
это позволяет.

### 4.3 Ноты и центы

```kotlin
// a4 конфигурируем: 415..466 Гц
fun frequencyOf(midi: Int, a4: Double) = a4 * 2.0.pow((midi - 69) / 12.0)
fun cents(f: Double, target: Double) = 1200.0 * log2(f / target)
```

Standard tuning (A4 = 440): E2 82.407, A2 110.000, D3 146.832, G3 195.998, B3 246.942,
E4 329.628 Гц. Все строи задаём списком MIDI-нот, а не частотами — частоты производны от
эталона A4.

Выбор целевой струны: минимум |cents| до нот текущего строя. Отклонение всегда
считается от целевой струны; даже при большом отклонении хроматическую ноту вместо
струны не показываем. Новую струну выбираем после нескольких согласованных измерений.

## 5. Архитектура

```
:app        Compose UI, ViewModel, настройки (DataStore), разрешения
:audio      MicSource — обёртка AudioRecord, эффекты, роутинг, lifecycle (Android-модуль)
:core-dsp   чистый Kotlin/JVM: Biquad, Decimator, Yin, PitchTracker, Note, Tuning
```

- `:core-dsp` — `java-library`, **без зависимостей от Android**. Тесты гоняются на JVM за
  секунды, DSP можно проверять на синтетике и на реальных WAV без эмулятора. Это главный
  архитектурный выбор спека.
- Поток данных односторонний: `MicSource: Flow<FloatArray>` → `PitchTracker` →
  `StateFlow<TunerUiState>` → Compose. Никаких колбэков обратно в аудио-поток.
- DI не нужен: зависимостей мало, собираем вручную в `MainActivity`/`ViewModelProvider.Factory`.
  Hilt/Koin для трёх объектов — лишний вес и время сборки.
- Настройки — `androidx.datastore:datastore-preferences` (строй, A4, вибро, keep-screen-on,
  тема).

**`TunerUiState`** (единственный источник правды для UI):

```kotlin
sealed interface TunerUiState {
    data object NeedsPermission : TunerUiState
    data object PermissionDeniedPermanently : TunerUiState
    data object MicBusy : TunerUiState
    data object Listening : TunerUiState                       // до первого распознавания
    data class Detected(
        val frequencyHz: Double,
        val noteName: String,          // "A2"
        val cents: Double,             // полное отклонение от целевой струны; стрелка ограничена ±50
        val stringIndex: Int,          // индекс в текущем строе
        val inTune: Boolean,           // |cents| <= 5
        val confidence: Float,
    ) : TunerUiState
}
```

## 6. UI / UX

Один экран, вертикальная компоновка, Material 3, тёмная тема по умолчанию (тюнером
пользуются на репетициях и сцене).

После проверки на устройстве: высота блока показаний фиксирована и не меняется при
переходе между тишиной и детекцией; последнее показание сохраняется. Над стрелкой
одна строка с номером струны, нотой и частотой. Под стрелкой — центы и направление
подстройки; при попадании в ±5 центов рядом с числом появляется галочка. Под блоком
отображается движущаяся зелёная волна уровня микрофона. Струны подписаны номером
6–1 и нотой с октавой. Настройки открываются кнопкой-иконкой без текста.
Весь текст приложения — английский.

```
┌──────────────────────────────┐
│ TUNE   Standard ▾      ⚙     │  заголовок, строй и настройки
│                              │
│   STRING 5 · A2 · 110.0 Hz  │  строка не исчезает в тишине
│         ╲    │    ╱          │  дуга −50…+50 ¢ со стрелкой
│      ╲       │       ╱       │  зелёная зона ±5 ¢
│                              │
│       −7 ¢ · TIGHTEN        │  отклонение от струны
│                              │
│  6 E2  5 A2 ... 1 E4        │  номер и нота каждой струны;
│      ●                       │  тап = ручная фиксация
└──────────────────────────────┘
```

Требования к реализации:

- **Стрелка рисуется в `Canvas`, а не через рекомпозицию.** Значение держим в
  `Animatable<Float>`/`MutableFloatState` и читаем **внутри** draw-лямбды (deferred read),
  чтобы 47 обновлений/с не вызывали рекомпозицию дерева. Анимация — `spring(dampingRatio =
  0.75f, stiffness = Spring.StiffnessMediumLow)`: критически демпфированная стрелка вместо
  дёрганья.
- **«В строе» сигналим тремя каналами, не только цветом:** положение стрелки в зелёной
  зоне + заливка зоны + гаптик `HapticFeedbackConstants.CONFIRM` (однократно, с
  cooldown 800 мс, отключаемо; на Android 10 константы `CONFIRM` нет — фоллбэк
  `Vibrator.vibrate(VibrationEffect.createPredefined(EFFECT_CLICK))`). Цветовая слепота и
  сцена с плохим освещением — реальные условия использования.
- **Доступность:** у гейджа `contentDescription`, обновляемый через
  `liveRegion = LiveRegionMode.Polite` («A2, 7 центов ниже»), но не чаще 1 раза в секунду,
  иначе TalkBack захлебнётся. Все тапы ≥ 48 dp. Текст масштабируется (sp, никаких
  фиксированных dp под шрифты), верстка выдерживает `fontScale = 2.0`.
- **Широкий экран / ландшафт:** гейдж и струны в две колонки при `widthSizeClass >= Medium`;
  проверяем через `WindowSizeClass`, не по `orientation`.
- Первый запуск: полноэкранная карточка с объяснением микрофона (одна фраза + кнопка),
  без онбординг-карусели.

### 7.1 Почему не «самые свежие» версии

Проверено скачиванием метаданных артефактов:

- **Compose BOM 2026.08.00 и 2026.09.00 (ui 1.12.x) требуют `compileSdk=37` и AGP ≥ 9.1.0.**
  Платформы `android-37` на машине нет, AGP 9.4 требует Gradle 9.6 (тоже нет в кеше).
  Поэтому потолок — BOM **2026.06.01**.
- `androidx.core:core-ktx` 1.19.x и `androidx.lifecycle` 2.11.0 — та же причина
  (`compileSdk=37`), пинятся на 1.18.0 и 2.10.0.
- AGP 9.4.x требует Gradle ≥ 9.6.0 и Build Tools ≥ 36.0.0 — это две докачки; AGP 8.13.2
  обходится установленным.

**Что придётся доустановить, только если понадобится обновлять стек** (одна команда, не
сейчас): `sdkmanager "build-tools;36.0.0" "platforms;android-37"` + wrapper на Gradle 9.6 —
после этого открывается путь на AGP 9.x и Compose 1.12+. Отдельно это понадобится для
публикации в Play, если/когда потребуется targetSdk 37; targetSdk 36 сейчас достаточно.

## 8. Производительность и энергопотребление

- Целевая нагрузка: < 3 % CPU одного ядра, < 40 МБ RSS, без GC-пауз в аудио-пути
  (проверяется отсутствием аллокаций: прогон через Android Studio Memory Profiler —
  плоская линия при работе тюнера).
- В тишине детект не запускается (гейт по RMS) — основной режим экономии.
- Никаких `Handler`-таймеров и polling: только блокирующее чтение микрофона.
- `StrictMode` (`detectAll` + `penaltyLog`) в debug-сборке.

## 9. Приватность и Play

- Ни одного байта наружу: нет `INTERNET` в манифесте, нет SDK третьих лиц.

## 10. Тестирование

**Unit (`:core-dsp`, JVM, быстрые — основная масса тестов):**

- синтетика: чистые синусы на всех 6 нотах × {−50, −10, 0, +10, +50} центов ×
  {A4 = 415, 440, 466} → ошибка детекта < 1 цента;
- гитароподобный сигнал: основная + гармоники 2–6 с затухающей огибающей и лёгкой
  негармоничностью → та же точность, **без октавных ошибок** (отдельный тест на E2 и A2 с
  усиленной второй гармоникой);
- шум: белый шум на −20 dB к сигналу → точность < 3 центов; чистый шум → `confidence`
  ниже порога, детекта нет;
- затухание: экспоненциальный спад до −50 dBFS → корректный переход в `Silence`;
- сглаживание и гистерезис: скачок частоты между соседними нотами не даёт мигания;
- `Cents`/`Note`: round-trip midi ↔ frequency ↔ cents, границы диапазона.

Фикстуры генерируются кодом в тестах (никаких бинарников в git), плюс 3–4 коротких
реальных записи `.wav` (E2/A2/E4, чистый и перегруженный звук) в `test/resources` как
регрессионный набор.

**Инструментальные (минимум):**

- сценарий разрешения: grant / deny / deny-permanently (`GrantPermissionRule` и
  `UiAutomator` для системного диалога);
- `MicSource` стартует и освобождает `AudioRecord` на реальном устройстве; после `onStop`
  индикатор приватности гаснет;
- Compose UI-тест: `TunerUiState.Detected` → на экране правильные нота/центы (проверка
  через `contentDescription`, не через пиксели).

**Ручная матрица:** основное устройство — телефон на Android 10/11 (API 29–30): именно на
нём проверяется штатный путь, и с высокой вероятностью там **нет** поддержки `UNPROCESSED`,
то есть рабочей окажется ветка `VOICE_RECOGNITION` + ручное отключение AGC/NS — её и надо
отлаживать в первую очередь (залогировать выбранный источник и реально отключённые эффекты).
Дополнительно: эмулятор на установленном образе **API 30** (`system-images/android-30`) —
совпадает с телефоном и позволяет прогонять UI-тесты без него; образов API 36 на машине нет,
поэтому targetSdk-поведение (edge-to-edge, insets) проверяем на физическом устройстве.
Если появится второе физическое устройство другого вендора — прогнать матрицу и на нём.
Проверить: входящий звонок, сворачивание, поворот, `fontScale = 2.0`, тёмная/светлая тема,
режим экономии батареи, а также что воткнутые наушники и подключённая BT-гарнитура **не**
переключают вход — тюнер продолжает слушать встроенный микрофон.

## 11. Приёмочные критерии

1. Определяет все 6 струн стандартного строя, взятых обычным щипком на акустике с 30 см,
   с ошибкой ≤ 1 цент относительно эталонного тюнера.
2. Задержка от щипка до устоявшегося показания ≤ 150 мс; стрелка не дрожит больше ±2
   центов на устойчивом тоне.
3. Нет октавных ошибок на E2 и A2 в 50 последовательных щипках.
4. В тишине и в шуме (без инструмента) не показывает ложных нот.
5. Микрофон освобождается при уходе приложения в фон (индикатор приватности гаснет,
   проверяется в Privacy Dashboard).
6. Переживает поворот экрана и смену темы без перезапуска захвата.
7. Все unit-тесты `:core-dsp` зелёные; `./gradlew build` без warning'ов у своего кода.
8. TalkBack озвучивает текущую ноту и отклонение; UI не ломается при `fontScale = 2.0`.
9. Release APK < 3 МБ, без `INTERNET` в итоговом манифесте (проверяется
   `aapt2 dump badging`).

## 13. Риски и решения

| Риск | Решение |
|---|---|
| Вендор всё равно применяет AGC/NS к `UNPROCESSED` | Явное отключение эффектов по session id; ручная проверка на Samsung; фоллбэк-цепочка источников |
| Октавные ошибки на низких струнах | Проверка субгармоники в YIN + тест-набор с усиленной 2-й гармоникой |
| «Тихий» микрофон после того, как его забрало другое приложение | `AudioRecordingCallback` + страховка по нулевому RMS, явное сообщение пользователю |
| Дрожание стрелки раздражает сильнее неточности | Медиана + EMA в центах + spring-анимация; параметры сглаживания вынести в константы и настроить на реальном инструменте |
| Рекомпозиция 47 раз/с сажает батарею | Отрисовка через deferred read в `Canvas`, замер в Layout Inspector (счётчик рекомпозиций = 0 при работе) |

## 14. Открытые вопросы

`applicationId` приложения — `dev.mangelov.tune`, имя — «Tune».

1. Нужен ли режим «по слуху» (воспроизведение эталонного тона через `AudioTrack`)? Дешёвая
   и популярная фича, но это уже вывод звука — отдельный подраздел спека.
2. Список альтернативных строёв: предложенные пять или шире (Open D, Drop C)? Нижняя
   граница диапазона (65 Гц) уже заложена под Drop D/DADGAD; Drop C (C2 65.41) потребует
   сдвинуть её до ~58 Гц и увеличить τmax до 415 — решить до реализации `Yin`.
